# PMP Prep by Calecutech

PMP exam prep for US candidates, built on the Recallio "Spaced Loop" method:
the app decides what to study, 10 questions at a time, at the times the
learner picks, planned back from their exam date. A free 10-card sitting, a
$39 one-time Stripe checkout, then the full original question bank, weekly
reports, cram mode and timed mocks. One Next.js codebase builds both the
website and the Android app. See `docs/ARCHITECTURE.md`.

| | |
|---|---|
| Web | `apps/pmp`, Next.js 16. Pages plus five route handlers under `/api` |
| Android | `apps/pmp/android`, Capacitor 7 wrapping a static export of the same pages |
| Android application ID | `com.calecutech.pmpprep` (permanent once uploaded to Play) |
| Question bank | `src/data/questions/{people,process,business}.json`, 180 original questions |

## How access works

There are no accounts. Paying produces a **licence key**, an HMAC-signed
statement that a Stripe Checkout session was paid, stored in the buyer's
browser.

1. `POST /api/checkout` creates a Checkout session for $39 (or `STRIPE_PRICE_ID`).
2. Stripe returns the buyer to `/unlock?session_id=…`, which calls
   `POST /api/license/claim`. The server retrieves the session from Stripe,
   checks it is paid, and signs a key.
3. `GET /api/bank` serves the full bank only to a valid key. The client caches
   it, so study works offline afterwards.
4. On a new device or the Android app, `POST /api/license/restore` re-issues a
   key for an email with a paid session.

The full bank is never bundled into the client. Only `src/data/sample.json`
(generated by `scripts/build-sample.mjs`) ships to the browser.

Progress (FSRS card states, review log, current sitting) lives in
localStorage on the device and does not sync between devices.

### Known gaps before launch

- **Restore by email is unverified.** Anyone who knows a buyer's email can
  unlock. Replace with an emailed magic link once an email provider is chosen.
- **Google Play billing.** The Android app shows no purchase button; it only
  signs in people who bought on the web. Check this against Play's current
  payments policy for US apps before submitting.
- **No webhook.** Access is granted by retrieving the session on return, which
  is enough for a one-time payment. Add `checkout.session.completed` handling if
  you want receipts, analytics or refunds to revoke keys.
- The Android app uses Capacitor's default icon and splash.

## Spaced repetition

`src/lib/engine` holds the Spaced Loop engine: FSRS (`ts-fsrs`) with four
ratings (Didn't get it, Tough, Understood, So simple), 10-card sittings, a
daily plan worked back from the exam date and a weekly report. v1 SM-2
progress is migrated on first open. Details in `docs/ARCHITECTURE.md`; the
rule-by-rule upgrade in `docs/UPGRADE_PLAN.md`.

## Environment

See `.env.example`. Server: `STRIPE_SECRET_KEY` (test key until launch),
`LICENSE_SECRET` (`openssl rand -base64 32`; rotating it revokes every key),
`PUBLIC_SITE_ORIGIN`, optional `STRIPE_PRICE_ID` / `PRICE_CENTS`. Android
build: `NEXT_PUBLIC_API_ORIGIN`, the deployed web origin.

## Running

```sh
cp apps/pmp/.env.example apps/pmp/.env.local   # fill in Stripe test key + secret
npm run dev --workspace=apps/pmp               # http://localhost:3200
npm test --workspace=apps/pmp                  # engine, mock and licence tests
npm run check:bank --workspace=apps/pmp        # question bank structure
```

Test card: `4242 4242 4242 4242`, any future date, any CVC.

### Android

```sh
npm run build:android --workspace=apps/pmp     # static export + cap sync
cd apps/pmp/android && ./gradlew assembleDebug  # needs the Android SDK
```

CI (`.github/workflows/pmp.yml`) runs the tests, the web build and a debug APK
build on every pull request touching `apps/pmp`, and attaches the APK to the
run.

## Deploying

A new Vercel project with root directory `apps/pmp`, e.g. at
`pmp.calecutech.com`. The Android build must point `NEXT_PUBLIC_API_ORIGIN`
at whatever origin that ends up on.

## Questions

All questions are original and written for the exam content outline in force
from July 2026 (People 33%, Process 41%, Business Environment 26%; verify
against pmi.org). Every one needs a PMP's review before launch. Options are
shown in random order on every showing, so their stored position means
nothing to the learner.
